# Football Star — module contract (read fully before writing a module)

The deployed game is ONE file, `game1.html`, **generated** by `./build.sh` from `src/`:

```
src/core.html          the original game (≈5,300 lines of CSS+HTML+JS) with 4 markers:  /* @css */  <!-- @html -->  /* @js */  /* @test */
src/css/NN-name.css    inlined into <style>, in name order
src/html/NN-name.html  inlined INSIDE <div id="stage"> (the 1000×620 stage that is scaled to the window), in name order
src/js/NN-name.js      inlined right before the init line (so everything in core.html already exists), in name order
src/test/NN-name.js    appended only by the test harness (./test.sh), after init
src/PLAN.md            the master design plan (numbers, rules). Your module's section is the spec.
```

Run `./build.sh` to regenerate `game1.html`. **Never edit `game1.html` directly.**

## Hard rules for module authors
1. **Do not edit `src/core.html`, `src/js/00-econ.js`, `src/js/05-cosmetics-data.js`, `build.sh`, `test.sh` or another module's files.** Only create/edit files named with YOUR module's prefix (`src/css/NN-name.css`, `src/html/NN-name.html`, `src/js/NN-name.js`, `src/test/NN-name.js`). If you truly need a change in the core, append an exact, minimal request to `src/CORE-REQUESTS.md` (what line, what change, why) and work around it meanwhile by monkey-patching (see below). The integrator applies the requests afterwards.
2. **Never run `./build.sh` alone** (it overwrites the shared `game1.html` while others work). Run **`./test.sh <name>`** instead: it builds a private copy with the foundation (`00-*`, `05-*`) + only the files whose name contains `<name>`, loads it in headless Edge, and prints `{"errs":[...script errors...], "log":[[test, PASS|FAIL]...]}`. It must end with `"errs":[]` and no FAIL. Write real tests (open your screen, click your buttons through `.click()`, check `prog` fields, simulate a match via `beginMatch(CHARS[0],CHARS[1]); state='play'; score.me=2; endGame();`). Tests run with an EMPTY localStorage each time. Use `TASSERT(name, cond)`, `TLOG(name, value)` and finish with `TDONE()`; wrap in `(async()=>{ await new Promise(r=>setTimeout(r,200)); ... TDONE(); })();`.
3. **Monkey-patching is the way to change core behaviour:** every core function is a plain `function` declaration, so you can wrap it: `const _old=showEnd; showEnd=function(o){ _old(o); /* your extra */ };` or replace it entirely (`updateAI=function(dt,ai,side,opps,mate){...}`). Core `let` variables (`state`, `level`, `score`, `timeLeft`, `selected`, `mp`, `v2`, `training`, `matchFmt`, `overtime`, `matchEarn`, `dailyMatch`, `forcedOpp`) are globals you may read and set. Core `const` values are read-only but objects/arrays inside them are mutable (`PITCH_THEMES.x = {...}`, `I18N_RAW`).
4. **Every visible string in 4 languages** through `I18N_ADD({'mod.key':['עברית','English','العربية','Русский']})` and `T('mod.key', arg0, arg1)` (`{0}` `{1}` placeholders). Static markup text: give the element an id and add `STATIC_ADD({'#id':'mod.key'})`; `applyLang()` fills it (call `applyLang()` once at the end of your module so it applies at load). Hebrew is the main language; the page is RTL (`dir="rtl"`); use logical CSS (`margin-inline-start`) where direction matters.
5. **Kids under 13, phones first.** Buttons ≥ 44 px tall, font ≥ 18 px, one idea per screen, big emoji icons, no walls of text. Use the existing look: `.btn` with `.green/.yellow/.red/.purple/.blue`, `.btn.small`, `.btn.big`; modals are `<div class="overlay" id="x-modal"><div class="panel">…</div></div>` toggled with `classList.add/remove('show')` (the `#stage` scales them for every screen size; **put every modal inside `src/html/`**, which lands inside `#stage`). New full screens: `<section id="x" class="screen">…</section>` + `showScreen('x')` (hides all others). `hidden` attribute hides anything (`[hidden]{display:none!important}`). Scope your CSS to your ids/classes (prefix with your module name) — never restyle core selectors. Stage coordinates are absolute pixels in a 1000×620 box. Confirmations: `await ask(text)` (returns a Promise<boolean>; never `confirm()`).
6. **No new network calls except through `fbReq(path, method, body)`** (Firebase REST; `path` like `'users/abc'`; returns parsed JSON, `null` for "nothing there", `undefined` when the server is unreachable). `fbOn()` tells whether a server is configured. Never block the game on the network; everything must work offline.
7. **Progress** lives in `prog` (saved by `saveProg()`, localStorage) and `settings` (`saveSettings()`). Add your own namespaced fields (`prog.dm`, `prog.shop`, …) with defaults applied lazily (`prog.dm = prog.dm || {...}`) — never assume they exist, never wipe other fields. Dates: ALWAYS `now()` / `dayKey()` / `weekKey()` / `isSunday()` / `dayCounter('field')` (server-synced), never `Date.now()`/`new Date()` for anything that hands out rewards.
8. Keep your module self-contained and defensive: check `typeof otherModuleFn==='function'` before calling anything from another module (modules load alphabetically but all are optional). Expose your public functions as plain top-level `function` declarations (no IIFE wrapping of the public API).
9. Performance: no per-frame DOM work outside the existing `render()`; animations with CSS; build big DOM only when a screen opens.
10. When done, write `src/NOTES-<name>.md`: what you built, public functions, hooks used, `prog` fields, open questions, and anything the home screen should wire (buttons → functions). Then report the same in your final message.

## Core API you can rely on (all global)
**Wallet / rewards (00-econ.js):** `ECON` (every number: payout tables, caps, chest/mission/calendar values — add your own sub-object `ECON.shop={...}` with `Object.assign(ECON,{shop:{...}})`), `prog.coins/gems/keys/xpTotal/lvClaimed`, `addCoins(n,why) spendCoins(n)→bool addGems(n,why) spendGems(n) addKeys(n,why) spendKeys(n) addXP(n,silent)`, `myLevel() levelProgress()→{lv,have,need,pct} levelOf(xp) xpForLevel(n)`, `fmtNum(n)`, `payout(o)` (pure) and `applyMatchRewards(o)` (used by the core at the end of every match), `coinCapToday() coinCapLeft() dayCounter(field)→{key,n} weekCounter(field)`, `prog.streakDays prog.streakLast prog.freezes prog.streakBroken prog.streakNew` (the core stamps the day on every finished match: `stampStreakDay()`), `prog.matches prog.lastPlay prog.recent recommendLevel()`, `matchEarn` (while a match runs: `{coins,gems,keys,xp,goals,levelUps}`), `matchFmt` (`'quick'|'classic'|'golden'`), `ECON.formats`, `myFormat()`, `overtime`, `ask(text,yesLabel?,noLabel?)→Promise<bool>`, `startOfflineMatch(levelI, oppIdx?)`, `randomOpponent()`, `NextUp.add(fn)` where `fn()` returns `{prio, icon, text, action}` or null, `goldenFlash()`, `ballSVG()`.
**Hooks (`Hooks.on(name, fn)`), emitted by the core:** `'screen'(id)` after any `showScreen`; `'home'` inside `refreshHome()`; `'wallet'` after the pills update; `'coins'(n,why) 'spend'(n) 'gems'(n,why) 'keys'(n,why) 'levelUp'(lv)`; `'select'(charIndex)`; `'purchase'({type:'char',id,price})`; `'matchEnd'(info)` with `info={outcome:'win'|'lose'|'draw', stars, score:{me,op}, earn:{coins,gems,keys,xp,goals,levelUps}, pay:{coins,xp,key,parts:[[i18nKey,amount]...],bonus,mult,capped,base}|null, trophies, online, fmt, level, v2, training, overtime, opp:charId}` — fires AFTER the result card is shown (`#end` overlay with `#end-title #end-sub #end-score #end-stars #end-xp #end-btns #btn-end-again #btn-end-home2 #end-actions`); `'streakDay'(days)` the first match of a day; `'ev'(eventName, n)` for every gameplay event the weekly challenges see: `win winHard clean v2win online daily play goal header corner ice slide pk cup`; `'challengeDone'(id)`; `'heartbeat'(body)` right before the presence PATCH is sent (add fields to `body`); `'welcome'` after the welcome gift.
**Optional globals the core checks:** `skinFor(c)` → object merged over the character before drawing (kit colours `jersey shorts socks stripes numColor`, `boots`, `number`) — return null for no change; `ballSkin()` → SVG string or null; `eventMult()` → number ≥1 (the best single multiplier wins).
**Core game:** `CHARS` (80 characters: `{id,name,jersey,shorts,socks,stripes,numColor,number,skin,hair,...}`), `selected` (index), `nm(c)` localized name, `priceOf(c)`, `isUnlocked(c)`, `FREE_CHARS`, `PRICES`, `sprite(el,c,mood)` draws a character into an element, `playerSVG(c,mood,skin)`, `buildGallery() refreshPreview() refreshHome() updateXpBadge()`, `LEVELS` (6 levels: `{name,color,speed,react,kick,jump,err,power,smart,goals}`), `LEVEL_ICON`, `level` (current), `startGame(levelIdx)`, `beginMatch(c1,c2,opts)`, `state` (`'idle'|'countdown'|'play'|'celebrate'|'replay'|'end'|'paused'|'penalty'|'corner'|'training'`), `score`, `timeLeft`, `endGame()`, `goHome()`, `quitToHome()`, `pauseGame() resumeGame()`, `showScreen(id)`, `toast(msg, 'xp'|'ach'|'warn')`, `sfx.click() sfx.win() sfx.lose() sfx.kick() sfx.whistle() sfx.ice()`, `confetti.burst(n)`, `say(key,...args)` commentator, `netEv(str)` sends a text event to online guests/spectators (handled in `applyEvent`), `mp` (online session or null; `mp.role` `'host'|'guest'`, `mp.conns` on the host), `v2` (2v2 flag), `training` (`null|'shoot'|'pk'|'corner'`), `dailyMatch`, `dailyInfo()`, `achieve(id)`, `addTrophies(n)`, `rankOf(t)`, `RANKS`, `TROPHY_ROAD`, `weekChallenges() challengeEvent(ev,n)`, `loadStats()`, `isAdmin()`, `normName(s)`, `settings.name`, `fbKey(name)`, `esc(s)` HTML-escape, `clamp shuffle`, `$(sel)` = `document.querySelector`, `lang` (`'he'|'en'|'ar'|'ru'`), `LI` ({he:0,...}), `PITCH_THEMES`, `buildPitch(themeName)`, `pitchTheme`, `players P1 P2 P3 P4 teamL teamR ball`, `doKick(p,power) doSlide(p) doScissors(p) useIce() useFire()`, `updateAI(dt, ai, side, opps, mate)` (the bot), `KEYSETS`, `document.body.classList.contains('touch')` (phone).
**Cosmetics data (05-cosmetics-data.js):** `COSMETICS` array (`{id,type:'kit'|'boots'|'ball'|'stadium'|'celeb'|'title',name:[4],price,gems?,rarity,data,week?,welcome?}`), `cosById(id)`, `cosName(c)`, `cosOwned(id)`; ownership is stored by the shop module as `prog.cos={items:[ids]}` and equipped as `prog.eq={kit,boots,ball,stadium,celeb,title}`. Any module that GIVES a cosmetic calls `giveCosmetic(id)` if it exists (shop module) — otherwise push to `prog.cos.items` yourself (create the object).

## Headless testing tips
`./test.sh shop` → only your module + foundation. `window.__errs` collects script errors. The DOM is real (headless Edge): `$('#btn').click()` works, `getComputedStyle` works, no `localStorage` persistence between runs, no network. If the harness prints `NO RESULT`, a syntax error stopped the script: open `./last-test-build.html` in a browser or search the build for your file. Avoid `alert/confirm/prompt`.
