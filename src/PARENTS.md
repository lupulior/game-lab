# הוראות להורים — הגנה על השרת של "כוכב הכדורגל" (פעם אחת, כ-10 דקות)

היום כל מי שיודע את כתובת השרת יכול לכתוב בו. כדי שרק המשחק עצמו יוכל לכתוב, מפעילים ב-Firebase "התחברות אנונימית":
הטלפון של כל ילד מקבל מספר זיהוי אקראי (בלי שם, בלי סיסמה, בלי אימייל), והשרת מקבל כתיבות רק ממי שיש לו מספר כזה.
הילדים לא ירגישו שום דבר. אם לא עושים את השלבים האלה — המשחק ממשיך לעבוד בדיוק כמו היום, רק בלי גיבוי בענן ובלי ההגנה.

## שלב 1 — להדליק "Anonymous" ב-Firebase
1. נכנסים ל-https://console.firebase.google.com ובוחרים את הפרויקט של המשחק (`football-star-cc849`).
2. בתפריט השמאלי: **Build → Authentication**. אם זו הפעם הראשונה, לוחצים **Get started**.
3. לשונית **Sign-in method** → לוחצים **Add new provider** → בוחרים **Anonymous** → מעבירים את המתג ל-**Enable** → **Save**.

## שלב 2 — להעתיק את מפתח ה-Web API לתוך המשחק
1. בקונסול: גלגל השיניים ליד "Project Overview" → **Project settings**.
2. בלשונית **General**, בחלק **Your project** יש שורה **Web API Key** — מעתיקים את הערך (מחרוזת ארוכה שמתחילה ב-`AIza`). זה לא סוד: הוא נועד להיות בתוך האפליקציה.
3. פותחים את הקובץ `src/js/70-social.js` ובשורה הראשונה-שנייה מחליפים:
   ```js
   const FB_KEY='';
   ```
   ב:
   ```js
   const FB_KEY='AIza...המפתח שהעתקתם...';
   ```
4. מריצים `./build.sh`, מעלים את `game1.html` החדש (ומעלים גם את `GAME_VERSION` בשורה 1273 של `src/core.html` כמו בכל גרסה).

## שלב 3 — להדביק את חוקי האבטחה
1. בקונסול: **Build → Realtime Database** → לשונית **Rules**.
2. מוחקים את כל מה שכתוב שם ומדביקים במקומו את הבלוק מ-`src/PLAN.md`, **Appendix A** (מהשורה `{ "rules": {` ועד הסוגר האחרון).
3. לוחצים **Publish**.
   - החוקים נותנים: כל ילד כותב רק לשורה שלו; קודים, חדשות והגדרות — רק אדמין; גיבויים (`saves`) — רק מי שיצר אותם.
   - שורות ישנות שנכתבו לפני השינוי ממשיכות להיקרא כרגיל.

## שלב 4 — לרשום את עצמכם כאדמין (חייב, אחרת פאנל האדמין לא יוכל ליצור קודים)
1. פותחים את המשחק בטלפון/מחשב שלכם אחרי העלאת הגרסה החדשה ומחכים כמה שניות (ההתחברות האנונימית קורית מאחורי הקלעים).
2. נכנסים לפאנל האדמין (קוד האדמין במסך 🎁 קודים). בפאנל מופיע **"uid"** — מחרוזת של ~28 תווים. מעתיקים אותה.
   (אם הפאנל עדיין לא מציג uid: פותחים את כלי המפתחים בדפדפן → Console → מקלידים `myUid()` → Enter.)
3. בקונסול: **Realtime Database → Data** → לוחצים על ה-"+" ליד השורש → שם: `admins` → בתוכו "+" נוסף → שם: ה-uid שהעתקתם, ערך: `true` → **Add**.
   התוצאה צריכה להיראות כך:
   ```
   admins
     └─ AbCdEf123...(ה-uid שלכם): true
   ```
4. יש כמה הורים/טלפונים של אדמין? מוסיפים כל uid כשורה נוספת מתחת ל-`admins`.

## מה קורה אחר כך
- כל טלפון של ילד מקבל זהות אנונימית בפעם הראשונה ושומר אותה. אם הילד מוחק את נתוני הדפדפן — הזהות חוזרת דרך **קוד השחזור** (מסך "עוד" → "קוד שחזור", 10 אותיות; הגיבוי לענן אוטומטי, פעם בדקה לכל היותר).
- **מה יש בגיבוי ומה לא:** הגיבוי (`saves`) נשמר בשרת תחת **גיבוב (hash) של הקוד**, לא תחת הקוד עצמו — מי שמסתכל ברשימת הגיבויים לא יכול לשחזר אותם. בגיבוי יש את ההתקדמות, הסטטיסטיקה, הגביע והשם של הילד בלבד; **רשימת החברים (שמות של ילדים אחרים) לא עולה לשרת**. הקוד מוצג במשחק עם כפתור "העתק" בלבד — אין כפתור שיתוף, כדי שילדים לא יפרסמו אותו בקבוצה. הסבירו לילד: הקוד הוא כמו מפתח — לא שולחים אותו לחברים.
- **קוד למכשיר:** כשמקלידים קוד במכשיר חדש, ההתקדמות מועתקת והמכשיר החדש מקבל **קוד חדש משלו** (מוצג פעם אחת). הקוד הישן ממשיך לעבוד במכשיר הישן; כל מכשיר מגבה למקום משלו ואף אחד לא דורס את השני.
- אם האינטרנט חסום או ההתחברות נכשלת — המשחק רץ אופליין בדיוק כמו היום.
- לא חייבים לעשות את זה היום. כל עוד `FB_KEY` ריק, שום דבר לא משתנה.

## בעיות נפוצות
- **"Permission denied" בקונסול הדפדפן אחרי שלב 3** — שלב 1 או 2 חסרים (אין טוקן). בודקים ש-Anonymous מופעל ושהמפתח הודבק בלי רווחים.
- **פאנל האדמין לא יוצר קודים** — ה-uid לא נרשם תחת `admins`, או שנרשם מטלפון אחר. כל מכשיר = uid אחר.
- **רוצים לבטל הכל** — מחזירים `const FB_KEY='';`, בונים ומעלים; החוקים אפשר להשאיר (קריאה ממשיכה לעבוד) או להחזיר לקודמים.

## הערה על החוקים (גרסה ראשונה)
בגרסה הזאת שורות השחקנים בטבלה (`users`) עדיין נשמרות לפי השם ולא לפי המזהה האנונימי, לכן החוקים מרשים לכל מי שמחובר (אנונימית) לכתוב בטבלה. זה עוצר כתיבה מבחוץ (מי שאין לו את המשחק), אבל ילד עם ידע טכני עדיין יכול לשנות את השורה של מישהו אחר. המעבר למפתח לפי מזהה (שחוסם גם את זה) מתוכנן לגרסה הבאה.

## חוקי Firebase שצריך עכשיו (2026-10-10) — בלי זה המועדונים, הגיבוי והסטטיסטיקה מראים "אין חיבור"
בשרת היום מותר לכתוב רק ל-`users` ו-`codes`; הצמתים `clubs`, `clubCodes`, `official`, `saves`, `stats` חסומים (HTTP 401).
ב-Firebase Console → Realtime Database → Rules, מדביקים (אותה רמת פתיחות כמו `users` היום; הקשחה אמיתית לפי Appendix A ב-PLAN.md כשיהיה FB_KEY):
```json
{
  "rules": {
    "users":     { ".read": true, ".write": true },
    "codes":     { ".read": true, ".write": true },
    "saves":     { ".read": true, ".write": true },
    "stats":     { ".read": true, ".write": true },
    "clubs":     { ".read": true, ".write": true },
    "clubCodes": { ".read": true, ".write": true },
    "official":  { ".read": true, ".write": true },
    "hidden":    { ".read": true, ".write": false },
    "admins":    { ".read": true, ".write": false }
  }
}
```
אחרי "Publish" המועדונים עובדים מיד, בלי לבנות גרסה חדשה.
